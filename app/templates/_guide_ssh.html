SSH Key Guide

How to generate, export, and use SSH key pairs.

What This Tool Does

Generates SSH key pairs and stores them in an encrypted database. Keys are saved directly to disk on export, avoiding clipboard line-ending corruption that commonly breaks private keys on Windows.

Supported Algorithms

  • RSA 4096 (default) — broadest compatibility with legacy systems, firewalls, network gear, and older SSH servers. Works with Bitwarden SSH agent.
  • Ed25519 — modern, fast, small keys. Works with Bitwarden SSH agent. Preferred for new deployments.
  • ECDSA P-256 / P-384 — good performance and security. Not compatible with Bitwarden's SSH agent.
  • RSA 2048 — legacy fallback only. Use RSA 4096 instead.

Export Formats

  • OpenSSH (default) — -----BEGIN OPENSSH PRIVATE KEY----- format. Used by OpenSSH, Git, and most modern tools. Compatible with Bitwarden.
  • PEM (PKCS#8) — -----BEGIN PRIVATE KEY----- format. Used by older tools, Java, and some enterprise software. Also compatible with Bitwarden.

Passphrase Protection

Optionally encrypt the private key with a passphrase at generation time. You will be prompted for it each time the key is used. You can also add a passphrase during export without having set one at generation.

Keys without a passphrase grant access to anyone who obtains the file. Use a passphrase for production keys.

Importing into Bitwarden

Bitwarden can store SSH keys and use them via its SSH agent, so you never need the private key file on disk.

  1. Select your SSH key in the sidebar.
  2. Click Copy Private Key (Bitwarden) — this copies the full PEM-formatted private key to your clipboard.
  3. In Bitwarden, create a new SSH Key item.
  4. Paste the private key into the Private Key field. Bitwarden will auto-detect the format and extract the public key and fingerprint.
Bitwarden's SSH agent supports RSA and Ed25519 keys only. ECDSA keys cannot be used with the Bitwarden SSH agent.

Using the Bitwarden SSH Agent

  1. Enable the SSH agent in Bitwarden Settings → SSH Agent.
  2. Configure your SSH client to use Bitwarden's agent socket (Bitwarden sets the SSH_AUTH_SOCK environment variable automatically on most platforms).
  3. When you ssh to a server, Bitwarden prompts you to approve the key usage.
The private key must include the full PEM header and footer (-----BEGIN ... ----- / -----END ... -----). The Copy Private Key button includes these automatically.

Using on Linux / macOS

  1. Export the private key: select Private Key, format OpenSSH, click Download.
  2. Move the downloaded file to your SSH directory:
    mv ~/Downloads/keyname-id_key ~/.ssh/id_rsa
  3. Set correct permissions:
    chmod 600 ~/.ssh/id_rsa
  4. Export the public key separately, or click Copy Public Key and paste into ~/.ssh/id_rsa.pub.

Adding to the SSH Agent

ssh-add ~/.ssh/id_rsa

If the key has a passphrase, you will be prompted to enter it once.

Deploying the Public Key

Copy the public key to the target server:

ssh-copy-id -i ~/.ssh/id_rsa.pub user@hostname

Or manually append to ~/.ssh/authorized_keys on the server.

The private key file must have 600 permissions. SSH refuses to use a key with permissions that are too open.

Using on Windows (OpenSSH)

Windows 10/11 includes OpenSSH as a built-in optional feature.

  1. Export the private key in OpenSSH format.
  2. Move the file to C:\Users\<you>\.ssh\ (create the folder if it does not exist).
  3. Rename it to match the expected name, e.g. id_rsa or id_ed25519.

Windows SSH Agent

  1. Open Services (services.msc) and set OpenSSH Authentication Agent to Automatic, then start it.
  2. Run: ssh-add C:\Users\<you>\.ssh\id_rsa

Using with PuTTY

PuTTY requires its own PPK format. To convert:

  1. Export the key in OpenSSH format.
  2. Open PuTTYgen → Conversions → Import key → select the file.
  3. Click Save private key to create a .ppk file.
Direct download avoids the line-ending corruption that happens when pasting private keys through Windows clipboard into text editors. Always use the Download button rather than copy-pasting key files.

Adding to GitHub

  1. Click Copy Public Key in the key detail view.
  2. Go to GitHub → Settings → SSH and GPG keys → New SSH key.
  3. Paste the public key and give it a descriptive title.

Adding to GitLab

  1. Click Copy Public Key.
  2. Go to GitLab → Preferences → SSH Keys.
  3. Paste and optionally set an expiration date.

Deploy Keys (Read-Only)

For CI/CD or read-only repo access, add the public key as a Deploy Key on the repository settings page instead of your user account.

Use Ed25519 for GitHub and GitLab — it is their recommended algorithm and produces the smallest keys.
